# Rust 运动规划

`crates/robot-core/src/planner.rs` 是可独立运行、可取消的本地运动规划模块。它沿用公开的 mm／deg／`[w,x,y,z]` 数据约定，返回值使用 camelCase JSON 与桌面界面对接。算法使用双精度浮点；不通过网络或 Python 子进程计算。

## ABB 计算路径

1. 校验型号、起始关节、单位四元数及速度（1–2000 mm/s）。起点奇异或超限直接失败。
2. 用肩部到 TCP 的连杆长度三角不等式快速排除显然不可达的目标；不使用以世界原点为中心的“标称臂展球”，避免误拒绝高处有效目标。
3. 自动方向模式先尝试保持起始方向，成功时跳过方向网格构造。失败后才搜索有限组方向／工具滚转角，并按方向变化排序；这不是方向空间的全局最优搜索。
4. TCP 沿直线、姿态沿最短四元数弧插值。平移间隔不超过 5 mm、旋转间隔不超过 2°，最多 1601 个采样。
5. 逐点检查关节限位、cfx 连续、轴1／4／6相对起点不超过180°、相邻任一关节不超过15°。只有完整路径通过，才返回可导出的成功结果。

内部候选保留固定尺寸数值数组，中间采样不生成终点解的字符串标识；输出路径预分配容量。算法性能数据必须来自实际 release 构建基准，不能仅凭编程语言声称加速倍数。

`plan_move_l_with_cancel` 接受 `AtomicBool`；`plan_move_l_cancellable` 可组合取消和调用方截止时间。每次方向尝试和路径采样之间检查取消，取消只返回 `cancelled`，不暴露部分成功路径，也不修改任何全局运动状态。

## Path点的独立端点检查

`endpoint_inspection.rs`通过`inspect_endpoint_with_cancel`接收`{modelId, pose, seedJoints}`，只返回该robtarget的`IkSolution[]`。它不构造零距离MoveL，也不返回路径通过标志；因此点属性中的候选解与Path运行时的逐段规划相互独立。点面板本身不再提供单段运动检查入口。

输入校验型号、坐标、四元数和参考关节限位；输出逐解复核FK、配置、误差、重复ID及关节组合。`inverse_kinematics_cancellable`在解析分支枚举间检查取消，取消不返回部分候选。桌面IPC命令为`inspect_endpoint`，开发CLI使用`{"op":"inspect","request":...}`；前端`inspectEndpoint`复核结果并隔离过时响应，原生失败不退回浏览器计算。

单CPU后台保留前台运动／导出、端点检查、网格检查三个有界等待槽，按此顺序调度，避免点选时两类检查互相替换。前台可中断背景任务；自动检查不能取消用户的前台求解或导出。

当前配置监督仍针对已接入的 ABB IRB1100 模型。多品牌程序生成的适配层负责各品牌的姿态与程序格式；尚未接入的机器人／控制器不得被当作已验证支持。上述单段运动学规划仍是标称几何的离散检查，不单独包含碰撞、个体校准、动力学或控制器认证；打磨规划在运动学结果上另做机器人／工具包络与禁入区检查。


## 通用 URDF 六轴直线规划

`generic_kinematics.rs` 与 `generic_planner.rs` 接收基座至工具的完整固定变换、转轴和六个关节限位，保留 URDF 的执行器索引，不套用 ABB DH 或 robconf。`buildGenericChain` 从已校验的模型提取链；四款目录机器人的固定 URDF 对照可通过 `node scripts/generate-generic-chains.mjs --check` 重建核对。

逆解使用解析空间雅可比、固定 6×6 阻尼最小二乘、四元数对数误差与步长回溯。每个直线／姿态采样从上一个接受的关节解开始；检查数值收敛、限位、15° 相邻关节上限与取消。目标姿态从记录关节 FK 得出，最后还须在 0.001° 内匹配记录关节，随后首尾使用精确记录值重新计算 FK，不能把相同姿态的另一圈轴角当作原目标。

桌面命令 `solve_generic_motion` 与 ABB 运动共享前台有界队列。前端复核每个采样的 FK、直线、姿态弧和连续性；超时或原生失败不退回 TypeScript。浏览器参考实现使用单独 Worker。原生／TS 对照覆盖四款真实模型，另外用 Three.js 的独立 URDF FK 检查坐标和轴向。

`generic_pose_planner.rs`另提供世界TCP目标规划和Jog，包含任意基座变换与法兰到TCP偏置。逐采样转换目标并计算真实工具雅可比，旋转TCP时不能把偏置法兰误当作静止点。XYZ模式先保持当前方向，再作有界姿态松弛；明确提供方向时则严格保留方向目标。

`generic_endpoint_inspection.rs`使用最多64个确定性初值，返回最多32个经FK校验并去重的端点候选，供临时预览。它是有界数值搜索，不保证穷举所有逆解；不会生成ABB robconf。`generic_collision.rs`从已校验的目录网格构建BVH，按各visual及固定支链变换检查端点与禁入区，开放网格无法确定内部关系时保留“不确定”。

新命令`solve_generic_pose_motion`、`inspect_generic_endpoint`、`check_generic_collisions`分别共享前台、端点和背景等待槽；网格读取／哈希检查／BVH构建均在worker中执行并支持取消。控制器配置推导与控制器程序导出仍未适配。

## Path全段运行

Path右键“运行”和Path属性“运行 Path”使用同一运行流程。`program-runner.ts` 接收该Path按添加顺序解析的点，先逐段调用对应型号的规划器，再开始播放。它不合并其他Path，也不解释生成或手工编辑的模块源码。任何段失败都会标出该Path中的指令位置，不能先播放成功前缀。循环额外规划末点回首点，后续只重复闭合段与该Path其余运动段，不重复当前姿态到首点的初次接近段。

时间轴按已验证采样驱动同一机器人关节状态。停止取消规划或动画并保留当前显示姿态，运行期间禁止修改Path、点、模块、机器人及区域。Path 点的“移动至此”使用独立关节定位动画，只用于摆放仿真姿态，不返回直线轨迹验证结果。

普通示教Path的这套多段运动学规划不等同于打磨规划的禁入区检查，也不包含控制器动力学验证；Path生成的独立源码模块、Path运动仿真和现有 ABB 单段后处理API是不同能力。独立单段检查、播放、复制与导出界面已移除，底层规划与后处理接口及其验证仍保留。源码静态检查不产生运动验证结果。

打磨规划对各target位置／姿态的保留、连续关节配置选择、世界TCP到基座法兰的变换、结果失效及检查边界见[参考坐标系、工具与打磨路径](frames-and-grinding.md)。原生求解失败不得静默退回浏览器算法。
