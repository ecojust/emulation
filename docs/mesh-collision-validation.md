# 实际网格干涉：输入审查与独立验证

本记录针对 `public/models/` 中两款 ABB IRB1100 的 14 份原始 STL，合计 **294,340 个三角形**。来源为 work-r-labs/robots 固定提交 `ab6aa489855256de07ba46c7b45887fdbc42b607`，来源、原始许可及哈希见 [vendor/work-r-labs/SOURCE.json](../vendor/work-r-labs/SOURCE.json)，逐部件包围范围及 SHA-256 见 [link-bounds.json](../src/robot/link-bounds.json)。坐标沿用源网格的机械零位共同基座坐标，单位为 mm。

审查日期：2026-11-09。审查不修改、补洞、重定向或焊接原始 STL。本文件说明真实输入和回归用例；不将网格检查等同于完整路径、控制器或实体机器人验收。

## 可复查命令

```sh
python3 scripts/inspect-collision-meshes.py > /tmp/emulation-mesh-audit.json
python3 scripts/inspect-collision-meshes.py --weld-mm 0.000001 > /tmp/emulation-mesh-audit-1e-6.json
python3 scripts/inspect-collision-meshes.py --weld-mm 0.0001 > /tmp/emulation-mesh-audit-1e-4.json
```

[inspect-collision-meshes.py](../scripts/inspect-collision-meshes.py) 只使用 Python 标准库，输出逐文件哈希、拓扑、组件有向体积，以及下面十个真实网格用例的结果。任一固定用例的三角形命中数或射线奇偶观察变化会退出失败；射线结果与最终是否可可靠分类分别记录。脚本与产品检测实现独立，不调用 Rust、Three.js、BVH、BSP 或已有 OBB 检测代码。

上述三条命令均已实际执行通过；标准库脚本的 14 行精确拓扑计数与初次使用独立 NumPy 脚本得到的结果一致。持久脚本不依赖 NumPy，也不依赖那些临时文件。

## 多组件和内腔

闭合组件的有向体积按 `Σ dot(a, cross(b,c))/6` 计算，仅用于审查方向和内腔关系：

- 两型号的 base_link、link_6 均为单个正体积组件。
- 两型号的 link_5 均为一个正向外壳和四个负向内腔。每个内腔包含 44 个三角形，有向体积约 `-7.0312 mm³`。
- 580 型号的 link_2 包含一个正向外壳和十二个负向内腔；每个内腔 22 个三角形，有向体积约 `-0.04384 mm³`。
- 两个 link_3 的主要外壳都有边界缺陷，另有四个闭合负向组件；580 型号 link_4 的主要外壳有缺陷，另有两个闭合负向组件。不能因存在一些闭合组件，就将整个部件标为可靠闭合实体。

不能采用“落在任意闭合组件内部就算落在机器人内部”的并集规则：它会把空腔填成实体。内外判定应保留完整壳层的内腔语义。下面的真实 link_5 用例可以直接抓出这种错误。

## 真实回归用例

以下坐标都是机械零位网格坐标，关节角为 `[0,0,0,0,0,0]`。包围盒均为世界轴对齐，尺寸是完整边长。基座不随关节转动，因此前三个用例也可用于非奇异的默认起点；仅检查其他连杆是否可能进入同一区域即可。

| 包围盒空角 | `[75,75,80]` | `[4,4,4]` | 0 | `0,0,0,0,0,2,4,2,0,0` | 无交；原 OBB 正结果为误报 |
| 穿过表面 | `[0,70,100]` | `[4,4,4]` | 3 | `1,1,1,1,1,1,1,1,3,1` | 相交 |

另外以已有 FK 和逐连杆 OBB 独立排除过两款机器人的默认起点 `[0,20,-30,0,40,0]` 与近似端点 `[4.4,20.3,-30.4,-5.9,40.3,6.7]`：空角区域的候选均仅有基座。这条姿态检查与上述 Python 原始网格用例不同，不能把近似端点当作完整求解或路径验证记录。

### link_1：无表面交点仍无法确定实体内部

两型号的 `link_1` 原字节一致，SHA-256 为 `05f2ff6948f269f609f8b145955bc2f1017861111c889b64400518f37d8f0f40`。区域中心 `[0,85,180]`、尺寸 `[4,4,4] mm` 与该部件包围盒相交，实际表面命中数为 0，但该部件有一条非流形边，不能用这里观察到的偶数射线结果将整个实体内部判定为可靠无交。

此用例应保留 `uncertainLinks: [1]`，没有确定表面命中时 `collidingLinks: []`。独立检查过机械零位、默认起点和上述近似端点：候选都只有 link_1；J1=0° 与 4.4° 时表面命中数均为 0。因此 UI 可以在可达姿态下验证“无法确定”状态，不需要退回奇异零位。

### 补充法兰接触位置

580 型号 link_6 的 X 最大坐标为 `364 mm`。用中心 `[364.5,0,627]`、尺寸 `[1,1,1] mm` 的区域恰好接触该端面，独立 SAT 命中 7 个三角形；将中心改为 `[364.51,0,627]` 后间隙为 `0.01 mm`，没有表面交点。两者适合作为接触容差／分离回归的补充。法兰中心轴线 `[360,0,617]` 经过实际孔洞，不能因为它位于法兰包围盒中就将其当作实体内部。这一补充点已单独执行检查，未计入上述脚本的十个固定用例。

上述 1 mm 盒的命中来自盒内邻近面，`[364,0,627]` 本身并不位于该端面的实体三角形内；它不适合作为更小区域的切点。旋转和接触容差用例使用实际三角形 1112（从 0 编号）的质心 `P=[364,15.238862037658691,622.9183146158854] mm`，与原生／浏览器对照测试统一。该点到三角形三条边的最小距离约 `1.68357 mm`，可以避开孔洞和三角形边。

取关节 `[20,-10,0,35,15,20]`，用实际网格刚体变换 `T=F6(q)·inverse(F6(0))`，其旋转部分为 `R`，端面世界法向为 `n=R·[1,0,0]`。对边长 `0.2 mm` 的世界轴对齐盒，设置中心 `T(P)+n·(0.1·(|nx|+|ny|+|nz|)+gap)`，直接变换原始三角形后执行独立 SAT，已核对：

| 法向间隙 gap | 不扩张盒的实际表面命中 | 每轴半尺寸增加 `1e-6 mm` 后的命中 |
| --- | ---: | ---: |
| `0` | 1 | 1 |
| `0.5e-6 mm` | 0 | 1 |
| `2e-6 mm` | 0 | 0 |

这一用例区分几何接触与产品明确采用的数值接触容差；不能将容差内的正间隙描述为数学上完全重合。

## 独立数值检查方法与边界

表面检查对实际三角形逐一执行 triangle/AABB 分离轴测试：三个盒面法向、三角形法向和九个三角形边与盒轴的叉积，共十三类轴。接触计入相交，轴投影容差为 `1e-9 mm × 轴长度`；没有用连杆包围盒的正结果替代表面结果。

内外检查采用双面的 Möller–Trumbore 射线求交，方向取以下五个向量归一化后的正、反方向，总计十条：`(1,.371,.127)`、`(.219,1,.537)`、`(.163,.285,1)`、`(-.617,.421,1)`、`(.881,-.313,.577)`。排除距离不大于 `1e-7 mm` 的起点命中，交点距离相差不大于 `1e-6 mm` 时合并，避免共享边／顶点重复计数；这些固定用例的十条射线奇偶分类一致。

这些射线是独立回归证据，不代表“十条一致就能修复开放网格”。有边界、非流形或退化问题的原模型，不能仅因为没有表面交点就自动证明区域位于实体外部。可靠的表面交点可以直接报告；依赖实体内部的结论需要明确处理输入缺陷和数值不确定性。

## BSP／BVH 比较记录

BSP能够计算封闭网格的布尔交集。本次实测使用 `three-csg-ts` 3.2.0／Three.js 0.187.0；同时对照 `three-mesh-bvh` 0.9.18 的布尔命中查询原型，并用 `three-bvh-csg` 0.0.18 复核完整包含。BSP和BVH不是同一种输出：前者生成交集多边形，后者只回答接触／内外关系。

环境为Linux x64、Node.js 24.22.1、3 vCPU Intel Xeon Platinum 8573C。每项独立进程、60秒限时、1.5 GiB V8堆；事先读取475型号全部七个原始部件并构造缓存。下表计时不包含文件解析和缓存准备；BSP取3次中位数，BVH原型取30次中位数，内存为整个进程峰值RSS。

| 实际输入 | BSP求交中位数 | BSP峰值RSS | BVH查询原型中位数 | BVH峰值RSS |
| --- | ---: | ---: | ---: | ---: |
| 基座包围盒空角 | 1,400.43 ms | 830.95 MiB | 0.053 ms | 81.35 MiB |
| 基座表面穿透 | 1,301.33 ms | 894.16 MiB | 0.083 ms | 79.83 MiB |
| 基座完全包含2mm方块 | 1,031.81 ms | — | 0.100 ms | — |
| 默认姿态、区域覆盖4个连杆 | 5,348.14 ms | 1,076.92 MiB | 0.185 ms | 79.72 MiB |

空角和表面输入的BSP结果正确。上述完全包含用例中，`three-csg-ts` 返回零多边形，与独立三角面／十射线证据及 `three-bvh-csg` 的8mm³交集不一致；这只说明该库版本在此输入的结果不能直接用于本功能，不否定BSP理论。另一个合成立方体仅接触用例中，两种CSG都返回空体，符合零体积交集语义，但本产品仍须将接触判为干涉，不能只用交集体积大于零作为碰撞条件。

表中BVH原型使用单射线包含检查，用于比较“构造布尔结果”与“只查询相交”的成本，**不是最终产品三射线／拓扑检查的性能报告**。最终方案保留原始网格、缓存空间索引，检查三角面及整个闭合壳层的包含关系，无需每次生成切割后的几何体。BSP和CSG只用于开发比较，不加入产品依赖。

## 最终Rust实现的性能与取消

同一机器执行：

```sh
cargo run -p emulation-core --release --example collision_benchmark --locked
```

示例直接计时 `check_collisions` 内核，使用release构建，不含进程启动、JSON、IPC或渲染。模型按连杆惰性建索引，因此“冷”表示本次需要的连杆尚未缓存，不与上表一次构造七个部件的准备时间混比。

| 工作量 | 第一次 | 预热后均值 | 预热后P95 |
| --- | ---: | ---: | ---: |
| 1姿态 × 基座空角／表面／包含三区 | 16.957 ms | 0.0102 ms（100次） | 0.0104 ms |
| 默认姿态 × 默认／多连杆／腕部三区 | 90.738 ms（含余下连杆建索引） | 0.00473 ms | 0.00480 ms |
| 256姿态 × 64区、关节与坐标微扰 | 52.624 ms | 71.337 ms（5次） | 89.815 ms |

上限工作量返回8,192个确认命中、4,096个未确定的姿态／区域／部件组合，不是只测远离模型的快速排除。冷构建取消在设置标志后0.132ms返回，预热查询取消0.040ms返回；取消后的重新构建成功，耗时88.876ms，未污染缓存。这里只报告实际样本，不把5次P95或本机耗时当作所有形状、机器的最坏上界，也不以Rust与浏览器之间不相同的实现声称语言加速倍数。
