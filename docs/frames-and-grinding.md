# 参考坐标系、工具与打磨路径

工作区使用跨厂商的名称。机器人控制器的专有名称留在品牌数据和程序后处理层，场景对象不以某一厂商的指令命名。

| 工作区名称 | 含义 | 厂商术语示例 |
| --- | --- | --- |
| 参考坐标系 / Reference frame | 安装机器人或定位工件、路径的空间参照 | ABB 工件／用户坐标、FANUC UFRAME、KUKA BASE、安川用户坐标 |
| 机器人基座 / Robot base | 机器人运动学链的根坐标系 | 各厂商的基座／机器人坐标系 |
| 关节轴 / Joint | 机器人可运动的轴，按当前型号顺序显示 | J1–J6、A1–A6、S/L/U/R/B/T 等 |
| 法兰 / Flange | 机械臂末端的机械连接界面 | 法兰／机械接口 |
| 工具 / Tool | 工具的安装位姿、TCP偏置及几何包络 | ABB tooldata、FANUC UTOOL、KUKA TOOL、安川工具坐标 |
| 路径 / Path | 有序目标点及其空间参照 | 不直接等同于控制器程序或作业文件 |
| 目标点 / Target | 工具中心点的位置和方向 | 品牌数据可进一步显示 robtarget、位置寄存器或位置数据 |

表中的厂商术语只用于帮助理解。它们的存储结构、坐标层次和控制器语义并不完全相同，不能仅改名称就视为已完成控制器适配。

## 世界位姿与局部位姿

世界坐标保持Z轴向上，公开长度为mm，关节角为度，四元数采用`[w,x,y,z]`。机器人基座默认在世界原点，但允许挂到参考坐标系。路径可整体挂到参考坐标系，工具可挂到法兰。

对象的世界变换由父级世界变换与局部变换共同决定：

```text
world(object) = world(parent) × local(object)
```

改变父级时，先取得对象原世界位姿，再计算新局部位姿：

```text
local(new) = inverse(world(newParent)) × world(old)
```

因此重新挂接不会让对象瞬移或翻转。之后主动编辑父级的位置或方向，会使子对象跟随；这与“换父级时保留世界位姿”是两个不同操作。父子关系不能形成环路，也不能把机器人基座挂到它自己的法兰上。

机器人基座、法兰和工具中心点是不同坐标系。工具的安装位姿描述工具原点相对法兰的位置，TCP偏置描述加工中心相对工具原点的位置。运动求解需要将世界TCP目标转换成当前机器人基座下的法兰目标：

```text
world(TCP) = world(base) × base(flange) × flange(tool) × tool(TCP)
base(flange target) = inverse(world(base)) × world(TCP target)
                     × inverse(flange(tool) × tool(TCP))
```

路径中的位置由所属路径的参考变换解释；已有点不能因为机器人关节继续运动而改变。挂接、父级移动或工具修改之后，运动、预览和程序生成必须使用当前的完整变换链，不能把旧关节快照当成仍可到达新目标的证明。

## 统一工具方向

打磨输入由若干个目标点组成，每个点包含位置和姿态。统一工具方向默认取第一个目标点的方向，也可以明确调整；其余输入姿态与统一方向的差异需要显示，不能静默把用户输入的方向当作已逐点保留。

整条加工路径使用同一TCP方向，求解还必须保持连续关节分支，避免相邻点之间突然翻腕。四元数`q`与`-q`表示同一方向，判断方向差异时不能把它们算成180°或360°跳变。工具方向一致也不意味着机器人关节自动连续：两者分别检查。

生成结果先作为预览，点击“预览路径”会收起编辑表单，可在三维场景中旋转、缩放查看；“返回编辑”保留输入和有效结果。用户明确应用后才替换路径。失败、取消、过期的计算结果不得改写原有点；机器人型号、基座、参考坐标系、工具、输入点或禁入区变化后，需要重新规划。

## 检查范围

规划验证针对当前机器人运动学、建模的禁入区和工具／机器人包络。它需要覆盖接近首点、点间运动及规划生成的过渡段，而不只是检查输入目标点。无法可靠验证或超出计算预算的区间应报告失败，不能显示为通过。

“通过检查”仅指明确建模的范围。它不等同于实际打磨工艺、控制器动态、标定、夹具碰撞或实机验收；没有建模的对象不会凭空参与规划。路径转为品牌模块与运动验证相互独立，具体品牌输出能力见[程序格式](program-formats.md)。
