# 用户请求与行动记录

本目录帮助后续 agent 从可复查的状态继续工作。先读 [INDEX.md](INDEX.md)，再读最新记录及相关未完成记录，同时核对实际文件和 Git 状态。

## 记录规则

- 文件名为 `YYYY-MM-DD-NNN.md`，日期采用 UTC，序号每天从 `001` 递增。同一持续任务可以跨日期追加；独立新任务创建新文件并登记索引。
- 每条用户 prompt 原样记录并编号，保留补充顺序。原文不可得时明确注明，不得编造；秘密仅以 `[已脱敏：类型]` 替换并说明。
- 有意义的阶段后追加行动条目，说明实际变更、验证、证据和结果。发现之前判断有误时追加更正，保留原始过程。
- 状态使用 `in_progress`、`blocked`、`completed`、`cancelled`。`blocked` 写明具体缺项；只有本条请求已完成才标记 `completed`。等待用户提出下一项独立需求，不妨碍将已经交付的任务标记为完成。
- 仓库文件使用相对链接；提交、PR 和工作流使用完整链接。临时路径标注“临时，后续环境可能不存在”，不作为唯一交接入口。
- 保存证据摘要，不复制巨大报告。测试数量必须来自实际执行；计划执行、执行中、失败、通过和未验证分别说明。
- 区分本地修改、提交、推送、合并、构建和发布状态，不能把下一步计划描述成已完成。
- 不保存秘密、完整敏感输出或私有推理。记录可复查结论及简短决策理由。
- 多 agent 协作由主 agent 汇总记录，其他 agent 汇报各自结果，避免同时改同一日志段落。
- 最终回复前同步记录与索引，明确交付结果、限制和下一步。`INDEX.md` 每行至少包含记录链接、状态、用户目标、当前结果及下一步。

## 模板

```markdown
# YYYY-MM-DD · 任务名称

- 状态：in_progress
- 分支：实际分支
- 起点：实际提交 SHA
- 关联记录：无／相对链接
- 当前目标与边界：用户要求及本次实际范围

## 用户 prompt

### U1

> 可见用户原话；无法取得的原文明示不可得，不补写。

## 行动记录

### A1 · 阶段名称

- 动作与文件：实际做了什么。
- 决策摘要：采用方案的可复查依据。
- 验证与结果：实际命令、退出结果、必要计数。
- 证据：仓库链接、提交或工作流；临时路径注明可能失效。
- 限制与未完成：尚未验证、未提交、未推送或未发布的部分。

## 当前交接

- 已完成：已核实结果。
- 正在进行／阻塞：准确状态及缺项。
- 下一步：已授权的后续动作，或等待用户下一项需求。
- 提交与发布状态：实际提交／推送／合并／发布情况。
```
